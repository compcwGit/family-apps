# 부업 방향: 작은 앱 여러 개 → 광고 + 기능/광고 해제 구매

- 상태: 📐 설계 (구조 결정 중)
- 처음 기록: 2026-11-16

## 찬욱 목표 (원본)

- 이런 앱을 **많이 만들어서** Play 스토어에 올리고
- **광고** + **광고 제거·기능 해제 구매**로 부업 수익
- 그래서 **처음 구조를 잘 만들어 두고** 싶음

## 원칙 (찬욱)

- 세금은 많이 내도 괜찮다. 수입이 그만큼 많으면 된다
- **법을 어기면서까지는 하지 않는다** → 모든 결정에서 합법·정책 준수가 우선

## 합법 운영 체크리스트 (Claude 제안)

- [ ] 세금: 수익은 금액과 관계없이 신고, 사업자·통신판매업 필요 여부는 세무사 확인
- [ ] 회사 겸업 규정 확인
- [ ] Google Play 정책: 가족 정책, 광고 정책, 스팸(반복 콘텐츠) 정책
- [ ] 개인정보: 아이 개인정보는 **아예 수집하지 않는 설계** 유지
      (만 14세 미만 정보 수집 시 법정대리인 동의 등 의무가 생기므로 피하는 게 안전)
- [ ] 저작권: 그림·소리·폰트는 **상업적 이용 가능한 라이선스**만 사용, 출처를 `docs/assets-license.md`에 기록

## 구조 제안 (Claude)

앱마다 반복되는 것(광고, 결제, 부모 잠금, 저장, 빌드)을 **한 번만 만들고**, 새 앱은 화면과 내용만 만드는 구조.

```
family-apps/
├─ packages/core/        모든 앱 공통 (한 번 만들고 계속 재사용)
│   ├─ ads/              AdMob 광고 (아동용 설정 기본값)
│   ├─ billing/          광고 제거·기능 해제 구매, 구매 복원
│   ├─ parent-gate/      산수 부모 잠금
│   ├─ storage/          기기 내 저장
│   └─ ui/               공통 버튼, 축하 애니메이션, 소리
├─ apps/
│   ├─ stampplay/        앱마다 패키지 이름, 아이콘, 화면만 따로
│   └─ animalfriends/
├─ scripts/new-app       새 앱 뼈대 자동 생성
└─ docs/privacy/<앱>/    앱별 개인정보처리방침 (Pages로 공개)
```

- npm workspaces 모노레포, 저장소 하나
- Actions는 바뀐 앱만 빌드, 태그(`stampplay-v1.0.0`)로 출시용 AAB 생성
- 새 앱 만들 때: `scripts/new-app` → 화면 개발 → 비공개 테스트 → 출시

## ⚠️ 찬욱 확인 필요

- [ ] **회사 겸업 규정**: 근로계약·취업규칙에 겸업 제한이 있는지
- [ ] **사업자등록·세금**: 개인 계정으로도 광고·인앱 결제 수익을 받을 수 있음(결제 프로필 '개인' 선택 가능).
      다만 수익은 금액과 관계없이 5월 종합소득세에 근로소득과 합산 신고.
      인앱 결제에 사업자등록·통신판매업 신고가 필요한지는 의견이 갈림 → 세무사·홈택스로 확인
- [ ] **개인 계정 vs 조직 계정**: 개인 계정은 **새 앱마다** 테스터 12명·14일 비공개 테스트 필요.
      조직 계정(D-U-N-S 번호 필요)은 면제 → 앱을 많이 낼 계획이면 사업자등록 후 조직 계정이 유리할 수 있음
- [ ] **비슷한 앱 대량 출시 주의**: Play 스팸 정책(반복 콘텐츠)에 걸릴 수 있음. 앱마다 뚜렷한 차별점 필요

## 현실 점검 (Claude)

- 아동용 광고는 채워지는 양이 적어 광고 수익은 작을 수 있음 → **구매(광고 제거·기능 해제)를 주 수익원**으로 설계
- 앱 수보다 **앱 하나의 완성도와 리뷰**가 노출에 더 중요
